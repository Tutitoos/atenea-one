# v0.1.10 — notas y procedimiento de actualización

**Estado: PUBLICADA y DESPLEGADA en el piloto el 2026-11-03** (solo la imagen `control-plane`; ver §6) (tag firmado `v0.1.10` sobre `f12e91e`, 36 ficheros, cuatro imágenes `amd64` por digest; `verify.sh` con 0). Complementa la [0.1.9](v0.1.9.md) con un único cambio de interfaz.

## 1. Alcance

Base: tag `v0.1.9`, commit `93bdb45`. Cambios respecto a ella (comprobables con `git diff --stat v0.1.9 <commit>`; el resto son documentos):

| Pieza | Cambio |
| --- | --- |
| Panel (`apps/web/app/join-network.tsx`, `enrollment.tsx`) | Casilla **«Código para un equipo con un CLI anterior a la 0.1.9 (sin conectividad)»**, en el código de red (solo si el servidor anuncia conectividad) y en el formulario del token. Pide `?conectividad=0` (ya soportado por la API desde la 0.1.9) y enseña el comando de un CLI 0.1.8 o anterior: `sudo atenea network join '<código>' --stun-host <STUN>` (sin `--up`, que ese CLI no tiene), el aviso de `--relay-ca RUTA` y el paso `network up` aparte. Si el servidor no admite el código, el error se muestra en el panel. |

**No cambian:** CLI, agente, coordinator, relay, API (`docs/api/openapi.json`), formato del código, empaquetado, migraciones (la base sigue en `1..8`), overlays de despliegue ni la aplicación de escritorio. Los binarios salen con la versión `0.1.10` pero con el mismo código fuente que en la 0.1.9. **El panel se sirve desde la imagen del control plane**: para tener la casilla hay que desplegar la imagen nueva de `control-plane`; los agentes no necesitan actualizarse.

## 2. Compatibilidad y retroceso

- **Servidor y agentes:** sin cambios de comportamiento más allá de la interfaz del panel. Las dos versiones se mezclan sin problema (el panel y el API son los del servidor; los agentes de la 0.1.9 y la 0.1.10 son equivalentes).
- **Retroceso:** volver a la imagen `control-plane` de la 0.1.9 (`upgrade.yml` con el mapa anterior). No hay migraciones.
- **Overlays:** `union-codigo.yaml` y `anclas-remotas.yaml` no cambian. En esta versión las anclas remotas **siguen apagadas por decisión del responsable**.

## 3. Procedimiento

Igual que la [0.1.9](v0.1.9.md) §3 para publicar y desplegar el servidor (copia completa nueva verificada, imágenes precargadas por digest, `upgrade.yml` con `atenea_backup_verified=true`, rescue ya ensayado). Para esta versión solo cambia la imagen `control-plane` en lo funcional: basta con fijar esa por su `registry_digest` de `images.json` y dejar `coordinator` y `relay` como están (son equivalentes a los de la 0.1.9). **No hace falta actualizar agentes.**
